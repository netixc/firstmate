Audience: maintainer verification.

The internal [`stow` skill](../../.agents/skills/stow/SKILL.md) owns tiering, curation, archival, offload, and completion-receipt behavior.
[`docs/configuration.md`](../configuration.md) owns the current operator-facing startup-memory setting and estimate.

## Git-excluded local skill discovery and loading

The internal skill's offload destination relies on Pi discovering and loading a skill directory whose path is listed in the clone's local `.git/info/exclude`.
This check ran on 2026-08-15 with Pi 0.84.1 in a disposable git repository inside the task worktree and a guarded named non-default Herdr lab session generated by `bin/fm-herdr-lab.sh name`.
The helper provisioned and tore down the named lab through its lifecycle commands, every non-lifecycle Herdr call used `bin/fm-herdr-lab.sh run <session> ...`, and guarded teardown verified that the running default session was unchanged.
The unique sentinel appeared only in the skill body below the frontmatter, so returning it required the fresh Pi process to load the excluded skill rather than infer it from the prompt.

The probe repository and skill were created with:

```bash
set -eu
PROBE_ROOT="$PWD/.stow-excluded-probe-tmp"
rm -rf "$PROBE_ROOT"
mkdir -p "$PROBE_ROOT/.agents/skills/excluded-probe"
git -C "$PROBE_ROOT" init -q
cat > "$PROBE_ROOT/.agents/skills/excluded-probe/SKILL.md" <<'EOF'
---
name: excluded-probe
description: A neutral probe used when explicitly requested by name.
---

# Excluded probe

The sentinel token is STOW-EXCLUDE-LOAD-PI-6Q9V2.
EOF
printf '.agents/skills/excluded-probe/\n' >> "$PROBE_ROOT/.git/info/exclude"
git -C "$PROBE_ROOT" check-ignore -v .agents/skills/excluded-probe/SKILL.md
```

The exact Pi commands run in the lab pane were:

```bash
pi --version
pi --no-skills --skill .agents/skills --model openai-codex/gpt-5.6-sol --thinking low -p "Use the skill named excluded-probe, then reply with exactly the sentinel token stated inside its body and nothing else."
```

The exact observed output was:

```text
0.84.1
.git/info/exclude:7:.agents/skills/excluded-probe/	.agents/skills/excluded-probe/SKILL.md
STOW-EXCLUDE-LOAD-PI-6Q9V2
```

The `git check-ignore` line proves that the local exclude rule covered the skill body.
The exact sentinel reply proves that a fresh Pi process loaded that body from the filesystem while automatic skill loading was disabled and only `.agents/skills` was supplied explicitly.
The probe exited zero, its disposable repository was removed, and guarded lab teardown preserved the default Herdr session byte-for-byte according to the helper's fleet-state tripwire.
